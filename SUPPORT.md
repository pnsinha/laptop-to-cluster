# Support and issue reporting

Use public repository issues for content defects, workflow defects, accessibility barriers, and portability observations. Choose the dedicated form so maintainers receive the information needed to reproduce and route the report.

A technical report should include environment/center, scheduler and container-runtime names and versions, other relevant versions, exact commands, sanitized input or configuration, expected result, observed result, exit status, and redacted logs. Never publish credentials, usernames, allocation IDs, private hostnames, or sensitive paths.

Accessibility reports should identify the page, barrier, assistive technology or input method when relevant, and desired outcome. Portability observations should identify the center, scheduler/runtime, storage/network/security boundary, local adaptation, and result.

## Channel status and alternative contact

The primary channel is GitHub Issues and is considered available unless `RECOVERY.md` or the public site status says otherwise. If issues are unavailable, email `parmanandsinha@gmail.com` with subject `BSSw resource report`, identify the failed channel, and include the same sanitized fields. If email is also unavailable, use https://bssw.io/contact to request a project-maintainer handoff; do not send sensitive security details through that form.

Public summaries remove respondent-identifying information unless the respondent explicitly approves attribution.
